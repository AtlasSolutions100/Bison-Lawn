## D1 dispatched vs not-dispatched per job (calendar icon); complete / cancel / skip from the board; completing puts the job on the customer account for billing
Status: partial  Effort: M

### Evidence

No dispatched icon on rows (dispatch.tsx:563-719). Skip: status select on the row offers scheduled/on_the_way/in_progress/skipped (dispatch.tsx:582-594) via PATCH /jobs/:id (jobs.ts:447-510) which runs assessSkip and stores skipReason/skipBillable (crm.ts:346-362) and toasts the verdict (dispatch.tsx:536-541). Complete: row menu 'Complete & Invoice' (dispatch.tsx:695-705) -> POST /jobs/:id/complete (jobs.ts:517-609) creates the invoice in a transaction via createInvoiceForJob, attaches pre-payments, sets client lastServiceDate, recalcs balance — i.e. it does land on the customer account. Cancel: NO cancelled status exists anywhere (grep 'cancel' in jobs.ts/schema/spec: only the 'Delete Job' action, dispatch.tsx:706-714 -> DELETE /jobs/:id jobs.ts:512-515, a hard delete with no audit row). Returning a job to the waiting list is supported by the API (bulk-assign `dispatched:false`, dispatch-map.ts:39,70) but nothing in the UI sends it (dispatch-map.tsx:237-245 never sets dispatched).

### Approach
1) Add a terminal `cancelled` status: crm.ts jobs comment + new columns `cancelReason text`, `cancelledAt timestamp`; openapi.yaml enums at :1096 (listJobs status), :3298 (Job.status), :3359 (JobUpdate.status) plus `cancelReason` on Job/JobUpdate; codegen. In PATCH /jobs/:id (jobs.ts:473-486) handle `status==='cancelled'` like skipped (set cancelledAt, keep reason; clear on move-off), and make POST /jobs/:id/complete refuse cancelled the way it refuses skipped (jobs.ts:530-532 and the locked re-check at :544). Contractors must not be allowed to cancel: extend the key check at jobs.ts:460-466 to reject status 'cancelled' for non-admins. 2) Board row menu (dispatch.tsx:690-716): add 'Cancel job' (prompt for reason, PATCH status cancelled) and 'Return to waiting list' (useBulkAssignJobs with `{ jobIds:[job.id], dispatched:false, scheduledDate:null }`), keep Delete. Add `cancelled` to statusColors (dispatch.tsx:546-553) and to the status filter select (:70-77); disable the status select for cancelled like completed (:587). Count cancelled in SubLoadSummary alongside skipped (:421, :477-479). 3) Dispatched indicator: since the board only holds dispatched jobs, render a small Calendar icon + 'Not dispatched' chip only where a job is shown outside the board (waiting-list.tsx rows) and, on the board Date cell (:608-612), show a CalendarCheck icon when `job.dispatched` — cheap and honest. Add tests to integration.test.ts: cancelled job cannot be completed; contractor cannot cancel; 'return to waiting list' flips dispatched=false and clears scheduledDate.

### Risks
Status is free text in the DB; every consumer that switches on status must learn 'cancelled': my-jobs.tsx (:98, :197-205), dashboard.ts (:44, :99 counts completed only — fine), reports.ts, invoice review. A hard 'Delete Job' stays available and is destructive without audit; consider routing it through logAudit. Moving a job back to the waiting list needs its windowStart/End to still be valid or it silently disappears from a date-filtered waiting list (jobs.ts:115-119).
