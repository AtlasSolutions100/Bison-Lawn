# J — Reports, global search, alerts

## Conventions
ROUTES. Each feature is an Express 5 `Router` in artifacts/api-server/src/routes/<name>.ts exported default and registered in artifacts/api-server/src/routes/index.ts (`router.use(reportsRouter)` etc., order matters only for routers that carry public paths; put new admin-only routers anywhere after `webRequestsRouter`). Guard with `router.use(["/prefix"], requireAuth, requireAdmin)` (see reports.ts:10, dashboard.ts:17, billing.ts:37). `requireAuth`/`requireAdmin` live in artifacts/api-server/src/middlewares/requireAuth.ts; `req.appUser` is the DB user (id, name, role admin|contractor). Validate query dates by hand like reports.ts `validDate`/`resolveRange` (yyyy-mm-dd, from<=to, 400 otherwise); validate bodies with the generated zod schemas from `@workspace/api-zod` (e.g. `CreateTicketBody.parse(req.body)`, `GetQuickbooksProfitAndLossQueryParams.parse(req.query)`); a thrown zod error becomes a 400 via the shape-based handler in app.ts. Log with `req.log` / `logger` (lib/logger.ts). Audit trail: `logAudit({clientId, actorName: req.appUser?.name, action, description})` in lib/helpers.ts:18 writes `audit_events`; existing action strings are listed by grep (`estimate_sent`, `estimate_accepted`/`estimate_declined` built as `estimate_${status}` in estimates.ts public respond, `invoice_sent` billing.ts:313, `client_email_sent` clients.ts:127, `payment_recorded`, `payment_applied`, `job_completed`, `job_status`...). Raw SQL reports use `db.execute(sql\`...\`)` with CTEs as in lib/analytics.ts; the file's rule is that numbers come from fixed queries, never model-written SQL.

OPENAPI + CODEGEN. Every endpoint the web app calls must be declared in lib/api-spec/openapi.yaml (paths + components/schemas; operationId becomes the hook name: `getCostingReport` -> `useGetCostingReport`, `getGetCostingReportQueryKey`; POST/PATCH become `useXxx` mutations called as `mutate({ data, id })`). Then run `pnpm --filter @workspace/api-spec run codegen` (orval, lib/api-spec/orval.config.ts) which regenerates lib/api-client-react/src/generated/api.ts + api.schemas.ts (react-query hooks over the `customFetch` mutator, baseUrl /api, cookie auth) and lib/api-zod/src/generated (zod schemas: `<OperationId>Body`, `<OperationId>QueryParams`, `<OperationId>Params`) and runs `tsc --build` for the libs. NOTE: `GET /reports/:key` exists in reports.ts:41 but is NOT in openapi.yaml, so there is no hook for it yet. Spec is OpenAPI 3.1 (nullable written as `type: ["number","null"]`). Response `rows` for the assistant are typed as CostingRow in the spec (ReportAnswer, line ~2384); generic reports need a looser row schema.

WEB. Pages live in artifacts/bison-crm/src/pages/*.tsx, registered in src/App.tsx inside `<Route path="/x"><SignedIn><AdminRoute component={X} /></SignedIn></Route>` and added to `ADMIN_NAV` in src/components/layout/admin-layout.tsx (sidebar only; there is no top header bar — the layout is sidebar + `<main>`; FeedbackButton is the only floating element). Data via generated hooks: `useGetCostingReport({from,to})`, mutations `ask.mutate({ data: {...} })`; override query options with `{ query: { enabled, queryKey: getXxxQueryKey(params), retry:false } }` (books.tsx:103). Invalidate with `queryClient.invalidateQueries({ queryKey: ['/api/clients'] })` (clients.tsx). UI is shadcn in src/components/ui (Card, Table, Dialog, Tabs, Alert, Skeleton, Badge, Input, Button; `command.tsx` = cmdk Command/CommandDialog is present but unused). Toasts: `useToast()` from src/hooks/use-toast.ts (`toast({title, description, variant:'destructive'})`). Router is wouter: `useLocation`, `useSearch`, `Link`; deep links use query strings (`/invoices?clientId=12` invoices.tsx:24; `/estimates?clientId=12&new=1` estimates.tsx:251). Money formatting: `money()` helper pattern in reports.tsx:12. Dates: date-fns `format(..., 'yyyy-MM-dd')`. Use `data-testid` attributes on interactive elements (dashboard.tsx StatCard).

DB. Schema is lib/db/src/schema/crm.ts (drizzle pgTable; export table + `$inferSelect` type; re-exported from `@workspace/db`). No migrations: after editing the schema run `pnpm --filter @workspace/db run push` (drizzle-kit push; DATABASE_URL must be set). NEVER `push-force` (DEPLOY.md:75). Adding a UNIQUE constraint to a populated table must be done by hand SQL first (DEPLOY.md:84-118). scripts/post-merge.sh runs install + `pnpm --filter db push` + typecheck. Booleans/text with defaults are safe to add; prefer text status columns with a comment listing values, like the rest of the file.

TESTS. Node's built-in runner: artifacts/api-server/test/*.test.ts run with `tsx --test` and chained in `package.json` "test" (add a new `test:reports` script and append it to the chain). Harness pattern (integration.test.ts:1-70): set `process.env.NODE_ENV="test"` and `process.env.TEST_AUTH_TOKEN=<random>` BEFORE `await import("../src/app.ts")`, `app.listen(0)`, then call `fetch(baseUrl + '/api/...')` with headers `x-test-user-id: <users.id>` and `x-test-auth-token: <token>` (requireAuth.ts:100-118 accepts them only when both env vars are set). Seed rows directly with drizzle (`db.insert(usersTable).values({clerkId:'test_admin_'+stamp, name, role:'admin', roleSource:'owner_assigned'})`), record ids, delete them in `after()`. Point DATABASE_URL at a throwaway DB. Browser e2e (lib/e2e, Playwright) boots the API with the same bypass plus `VITE_E2E_AUTH_BYPASS=1` for the web gate (src/lib/e2e-auth.ts).

EMAIL. Outbound email is Gmail API send-only (lib/gmail.ts `sendRawGmailMessage`, wrappers `sendClientEmailViaGmail`, `sendCustomerMessageViaGmail` in customerMessageDelivery.ts:80, invoice/estimate/letter delivery libs). There is no inbox read scope (privacy.tsx:62 promises the app cannot read mail), so real bounce-backs are invisible; only send-time failures are recorded (letter_sends.status/error, estimates.deliveryState/lastDeliveryError, suggested_actions.messageDeliveryState/messageDeliveryError, audit `estimate_delivery_failed`). Owner notification emails follow lib/feedbackNotification.ts (env `FEEDBACK_NOTIFY_EMAIL`, never throws). AI: lib/aiAssistant.ts calls xAI (`XAI_API_KEY`, `XAI_MODEL`, default grok-3) and only routes to a curated report key + summarises rows.
