## Conventions
Monorepo layout and commands: pnpm workspace; API artifacts/api-server (Express 5), web artifacts/bison-crm (React 19 + Vite + Tailwind v4 + shadcn + wouter + TanStack Query), schema lib/db/src/schema/crm.ts, spec lib/api-spec/openapi.yaml. Full typecheck: pnpm run typecheck (root package.json). Dev: node dev.mjs runs both with .env and proxies /api (vite.config.ts:60). ARCHITECTURE.md:1-60 is the canonical cheat sheet.

Schema changes: edit lib/db/src/schema/crm.ts only (pgTable, snake_case column names, export the $inferSelect type; date-only values are text yyyy-mm-dd, instants are timestamp; money is doublePrecision rounded with roundMoney in billing). There are no migration files: push with pnpm --filter @workspace/db run push (drizzle-kit push, needs DATABASE_URL; drizzle.config.ts fixes the Windows glob). Read what push proposes before confirming; NEVER run push-force (DEPLOY.md:63-95 - it once offered to truncate invoices to add a unique constraint; unique constraints on populated tables are added by hand with psql). Nullable columns and booleans with defaults push cleanly. In production: bash /root/bisonlawn/deploy/deploy.sh then docker compose --env-file .env.deploy exec app pnpm --filter @workspace/db run push. The e2e suite runs push itself (lib/e2e/README.md).

API contract and codegen: lib/api-spec/openapi.yaml (title must stay 'Api') is the source of truth. Add a path with an operationId, tag, parameters and request/response $refs, and schemas under components/schemas (nullable as type: ['string','null']; enums listed inline). Then run pnpm --filter @workspace/api-spec run codegen (orval.config.ts) which regenerates lib/api-client-react/src/generated/api.ts (react-query hooks named use<OperationId> e.g. useListClientPhotos, useUpdateClient; key helpers get<OperationId>QueryKey; types in api.schemas.ts, all re-exported from @workspace/api-client-react) and lib/api-zod/src/generated/api.ts (zod v4 schemas named <OperationId>Body / <OperationId>QueryParams / <OperationId>Params e.g. UpdateClientBody, CreateClientServiceBody, exported from @workspace/api-zod) and finishes with pnpm -w run typecheck:libs. Never edit generated files. Query params are coerced (boolean/number/string) by the zod config, but most routes read req.query manually as strings.

Route conventions: one Router per file in artifacts/api-server/src/routes/<name>.ts, default export, registered in routes/index.ts (order matters: a router with a blanket router.use(requireAuth) shadows later public routes - see comments index.ts:28-39), all mounted under /api (app.ts:105). Guard with router.use(requireAuth) then requireAdmin per route, or a path-list guard like clients.ts:28 router.use(['/clients','/client-services'], requireAuth, requireAdmin). req.appUser (id, name, role admin|contractor) is set by middlewares/requireAuth.ts. Parse bodies with the generated zod schema (const body = UpdateClientBody.parse(req.body)); a zod failure becomes a 400 with field messages via app.ts:159-169, so do not try/catch parse. Return 404 { error } for missing rows, 400 { error: plain English } for rule violations, 204 .end() for deletes. Hydrate pattern: batch-load related rows with inArray and map name fields (tickets.ts:11-26, jobs.ts:40-109); convert timestamps with toISOString when the spec says string. Write audit rows with logAudit({ clientId, actorName: req.appUser?.name, action: 'snake_case', description }) from lib/helpers.ts:18; friendly field names for client PATCH audit come from CLIENT_FIELD_LABELS clients.ts:144-153. Multi-row writes go in db.transaction(async (tx) => ...) and helpers accept an Executor tx (clients.ts:260, jobs.ts:536). Declare literal sub-paths (e.g. /clients/lead-sources) before /clients/:id. Contractor access to jobs uses canAccessJob (jobs.ts:297-302, copied in photos.ts:27-32); contractor PATCH allow-lists (jobs.ts:463, tickets.ts:72) are security boundaries.

Web conventions: pages in artifacts/bison-crm/src/pages/*.tsx registered in App.tsx:319-353 as <Route path=...><SignedIn><AdminRoute component={X} /></SignedIn></Route> (ContractorRoute for /my/*). Fetch only through generated hooks: const { data, isLoading, isError } = useListX(params); mutations useCreateX().mutate({ id, data }, { onSuccess, onError }); after a mutation either queryClient.setQueryData([`/api/clients/${id}`], fresh) or queryClient.invalidateQueries({ queryKey: ['/api/clients'] }) - query keys are the URL path (or the generated getXQueryKey(id)); conditional queries pass { query: { enabled, queryKey } } (client-detail.tsx:1365). Auth is cookie-based; never add bearer headers. UI is shadcn (@/components/ui/button, card, dialog, tabs, input, textarea, popover, table), lucide icons, useToast for feedback, plain <select> elements styled with the repo's class string, data-testid attributes on interactive controls, forms either react-hook-form + zod (clients.tsx NewClientDialog) or useState with a dirty check and Save button (client-detail.tsx ClientBilling/ClientRouting). Deep links use wouter useSearch/useLocation (estimates.tsx:247-279 clientId&new=1, invoices.tsx:19-33 clientId) and strip params after consuming. Blank inputs are saved as null, not '' (client-detail.tsx:703-721). Comments in this repo explain the business reason for a decision; match that style.

Tests: API tests are node:test files in artifacts/api-server/test/*.test.ts run with tsx --test, each added as a test:<name> script and chained into the test script in artifacts/api-server/package.json. Boot pattern (integration.test.ts:24-31, 68-73): set process.env.NODE_ENV='test' and process.env.TEST_AUTH_TOKEN=<random> BEFORE dynamically importing ../src/app.ts, then server = app.listen(0) and call fetch with headers x-test-user-id: <users.id> and x-test-auth-token: <token> (requireAuth.ts:96-118 only honours this when both env vars are set; the user row must exist, so insert admin/contractor users with db.insert(usersTable) in before() and delete them plus their clients in after(); client deletes cascade jobs/invoices/payments/audit). Needs a real DATABASE_URL (dev Postgres). Email is mocked by passing a GmailProxy function (clientEmail.test.ts:5-16). Browser e2e lives in lib/e2e (Playwright, in-process API with NODE_ENV=test, Vite with VITE_E2E_AUTH_BYPASS=1, harness.ts). Verification write-ups go under verify/<date>/<topic>/VERIFY.md and shipped decisions are recorded in FINDINGS.md; BACKLOG.md tracks Adam's feedback ids (26, 88, 96, 101, 118 are in this area).
