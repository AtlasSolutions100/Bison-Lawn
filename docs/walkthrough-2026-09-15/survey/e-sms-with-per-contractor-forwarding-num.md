### Approach
HONEST DESIGN FIRST. 'Customer never sees the contractor's real number' + 'replies go to the contractor' = a masked proxy number per contractor. There is no way to own, send from, or receive on a phone number without a carrier/CPaaS provider, so that half of E1 REQUIRES a paid provider; what can be built for free is (a) the whole app-side scaffold in 'not configured' mode, (b) a zero-cost `sms:` deep-link fallback, and (c) the provider adapter so flipping it on is an env change. Recommended provider: Twilio (or Telnyx, cheaper) via plain REST calls with fetch — mirror gmail.ts rather than adding an SDK, so build.mjs externals stay untouched. Approximate cost (verify at build time): ~US$1–1.15/mo per local number, ~$0.008/segment + carrier pass-through; US local numbers need A2P 10DLC registration (brand + campaign, small one-off fees and ~$1.5–10/mo campaign fee, approval days–weeks, needs EIN/business address) — unregistered traffic is filtered by US carriers; a verified toll-free number is the simpler alternative. Twilio's trial ($15 credit, verified recipients only, 'Sent from a Twilio trial account' prefix) is fine for development, unusable for customers. Email-to-SMS carrier gateways via the existing Gmail sender (e.g. 10digits@vtext.com) are free but unreliable, spam-filtered, AT&T retired its gateway in 2025, require knowing each customer's carrier, and cannot mask per contractor — mention to Adam only as 'not viable'. 'Free texting' in Service Autopilot was a paid add-on; the realistic promise is 'texting included in the CRM, Work Optional carries the ~$5–15/mo provider bill'. IMPLEMENTATION PLAN (sub-items E1a–E1f below give the detail): new lib artifacts/api-server/src/lib/sms.ts with an injectable `SmsProvider` seam (like GmailProxy), `smsConfigured()` (like aiAssistant.ts:24-26), Twilio adapter over fetch; new table sms_messages + nullable users.proxyPhone/proxyPhoneSid + clients.smsOptOut in lib/db/src/schema/crm.ts; new router artifacts/api-server/src/routes/sms.ts registered in routes/index.ts (public /inbound/sms and /inbound/voice mounted BEFORE jobsRouter like webRequestsRouter at index.ts:31-39); OpenAPI paths + `pnpm --filter @workspace/api-spec run codegen`; UI: 'Send Text' dialog on client-detail next to Send Email, texting-number field on team.tsx, 'Text customer' on my-jobs.tsx, SMS status card on settings.tsx; env SMS_PROVIDER/TWILIO_ACCOUNT_SID/TWILIO_AUTH_TOKEN/SMS_OFFICE_NUMBER in .env.example and .env.deploy.example; tests test/sms.test.ts (+ integration cases).

### Risks
The promise cannot be met without a paid provider; say so before building. A2P 10DLC/toll-free verification lead time (days–weeks) gates go-live, not code. STOP/HELP opt-out must be honoured (store clients.smsOptOut; Twilio Messaging Services auto-handle STOP but the app must stop sending). Free-text phone fields need normalisation before matching inbound numbers.

## E1d — inbound + forwarding: per-contractor proxy number; customer reply reaches the contractor; contractor reply relays back to the customer; customer only ever sees the proxy number; call forwarding on the same number
Status: missing  Effort: L

### Evidence
No inbound message path. The only public webhook is POST /inbound/web-request (web-requests.ts:96-106) authenticated by a shared secret compared with sha256+timingSafeEqual (web-requests.ts:18-28), declared above the router's `router.use(['/web-requests'], requireAuth, requireAdmin)` (web-requests.ts:108) and mounted ahead of jobsRouter's blanket requireAuth (routes/index.ts:28-39, which documents the outage caused by getting that order wrong). express.urlencoded is already enabled (app.ts:90) so Twilio's form-encoded webhook posts parse without extra middleware. Contractors are notified only by email (subNotification.ts:35-90). APP_PUBLIC_URL is required in production (app.ts:50-63, .env.deploy.example) and is the base for building webhook URLs.

### Approach
Provider-side: each contractor gets one dedicated Twilio number whose SmsUrl and VoiceUrl point at `${APP_PUBLIC_URL}/api/inbound/sms` and `/api/inbound/voice`. App-side, in routes/sms.ts ABOVE the requireAuth line: `POST /inbound/sms` — (1) validate `X-Twilio-Signature`: HMAC-SHA1 over (full public URL + form params sorted by key, values appended) with TWILIO_AUTH_TOKEN, compare with timingSafeEqual (web-requests.ts:20-28 style); build the URL from APP_PUBLIC_URL + req.originalUrl, not req.host (the app sits behind Caddy on loopback, docker-compose.yml:47-49). (2) `to = normalizePhone(req.body.To)`, `from = normalizePhone(req.body.From)`, `body = req.body.Body`. (3) Handle STOP/UNSUBSCRIBE/START keywords: set/clear clients.smsOptOut for the matching client and reply nothing more. (4) Resolve the line: user where proxyPhone = to (contractor line) else the office line (SMS_OFFICE_NUMBER). (5) If `from` equals that contractor's own `users.phone` (phoneKey match) it is a CONTRACTOR REPLY: pick the target thread — if body starts with `#<n>` use sms_messages id n's clientId, else the most recent inbound customer message on this line in the last 24h; send body (minus the #n prefix) to that customer FROM the proxy number; store as outbound with userId; if no thread found, text the contractor back 'No customer to reply to — start with #<id>'. (6) Otherwise it is a CUSTOMER message: match client by phoneKey(clients.phone) (also billing/additional contacts if desired); store inbound (status 'received', clientId, userId); forward to the contractor's real `users.phone` FROM the proxy number as `[#<msgId> ${clientName ?? from}] ${body}` (status 'relayed', relayedToNumber); if the line is the office line or the contractor has no phone, create a ticket (ticketsTable crm.ts:573-583, title `Text from ${name}`) so the office sees it; logAudit action 'client_sms_received'. (7) Respond `res.type('text/xml').send('<Response/>')` (always 200 — Twilio retries on non-2xx). `POST /inbound/voice` — same signature check; respond with TwiML `<Response><Dial callerId="${proxy}">${contractor.phone}</Dial></Response>` (or `<Say>` when no contractor phone) so calls to the proxy number ring the contractor with the proxy number shown to nobody's harm. Extract the routing decision into a pure function `routeInboundSms(input, ctx)` in lib/sms.ts and unit-test it with fixtures (no DB); integration-test the webhook by computing a valid signature in the test (TWILIO_AUTH_TOKEN set in-process like TEST_AUTH_TOKEN, integration.test.ts:24-30). Register: `router.use(smsRouter)` in routes/index.ts BEFORE `router.use(jobsRouter)` — put it right after webRequestsRouter (index.ts:39) with the same comment about the blanket requireAuth.

### Risks
Thread ambiguity when one contractor has several open customer threads — the #id prefix + 24h-recency rule must be explained on the contractor's phone in the forwarded text. Contractors' real numbers must be stored normalised or the 'is this the contractor' check silently fails and their reply is treated as a customer message. Signature validation breaks if the public URL differs by scheme/port/trailing slash from what Twilio was configured with — log the computed URL on failure. Twilio retries webhooks: dedupe on MessageSid (unique index like web_requests.external_id crm.ts:620-621). Voice forwarding adds per-minute cost. Group MMS/attachments (NumMedia>0) — store the media URLs or drop them explicitly.
